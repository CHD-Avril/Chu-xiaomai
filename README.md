# CHU-小麦点歌台

**CHU-小麦点歌台** 是长大校园广播点歌活动的线上征集入口。

它为同学们提供一个轻量、直接、好用的点歌空间：在开放征集期内，大家可以提交想听的歌曲，为喜欢的投稿点赞，也可以通过当前榜单看到本期校园歌单正在被怎样共同塑造。对广播台来说，它则是一个完整的线上运营台，可以发布公告、设置征集时间、归档历史歌单，并快速整理最终播放名单。

## 我们想做什么

校园广播里的点歌，本质上不只是“收集歌名”。它更像是一段小小的公共情绪：有人把一首歌投给朋友，有人想在放学路上听到熟悉的旋律，也有人只是想让某个瞬间被广播记住。

长大小麦君点歌台希望把这件事变得更清楚、更轻松，也更有参与感。

同学不需要加入群聊、不需要私信工作人员，只要打开页面，就能完成投稿和点赞；广播台也不需要在聊天记录、表格和截图之间来回整理，只需要在后台开启一期征集，就能等待大家把歌单填满。

## 网站体验

进入网站后，页面会展示当前点歌征集期的状态。

如果征集正在开放，同学可以填写歌曲名和歌手名完成投稿；提交后的歌曲会出现在歌单列表里，并和其他投稿一起接受点赞。歌单支持搜索、分页和排序，既可以看最热门的歌曲，也可以快速找到自己关心的投稿。

征集结束后，当前歌单会进入公示状态。页面保留结果展示，停止继续投稿和点赞，让本期歌单自然沉淀下来。

游客只能浏览，QQ 登录后才能投稿、点喜欢和点踩，页面会明确提示。正式期参与记录绑定 QQ 账号，换设备登录同一个 QQ 可恢复票态。手机首页优先展示投稿表单；榜单和往期每页显示 6 首，提供顶部上一页/下一页与底部页码，较多页数时可展开跳转。榜单中的每日随机推荐每次展示一首，可点击“换一首”或定位到对应歌曲；搜索时收起推荐。喜欢为主要操作，点踩为次要入口，人气排序前三名用黄色标记；投稿时间不再占用每行空间，完整名称仍可点击展开。

投票规则默认折叠，往期征集期选择器每页显示 5 期，选中后自动收起，并在下方展示征集日期；征集期和歌曲分别翻页。首页公告读取最近 20 条有效消息，每页展示 2 条，点击打开完整正文。管理入口位于页脚；QQ 登录使用腾讯官方原尺寸小图标搭配「QQ 登录」文字，采用白底、细描边和圆角按钮，放在电脑和手机的页头右侧，首页、榜单和往期均可直接找到。登录后原位置显示头像、昵称和退出入口；退出后恢复游客只读模式。

QQ 按钮素材来源与放置要求见 [QQ 互联网站前端页面规范](https://wiki.connect.qq.com/网站前端页面规范)。按钮图标保存在 `apps/user/src/assets/qq-login-icon.png`，以原始 16×16 像素展示。开发和生产均通过本站 `/qq` 授权后端登录，按钮使用可直接导航的链接，不先等待会话读取。后端按腾讯 Authorization Code 流程获取令牌、OpenID 和用户信息；AppKey 与令牌不会进入前端。回调检查一次性 state 和发起浏览器的 Cookie，登录后用 HttpOnly Cookie 恢复会话，退出会使服务端会话失效。QQ 登录不授予管理员或测试账号权限。

**只发布静态前端不能开通 QQ 登录。** 正式站必须同时运行 `apps/user/qq-auth` 服务并将 Nginx `/qq/` 请求代理到本机 3000；否则按钮无法完成真实授权，腾讯审核也无法看到本地改动。生产配置已启用 `/qq`，后端、初始化和部署步骤见 [QQ 登录接入](docs/QQ_LOGIN.md)。发布流程会打包授权后端、重启对应服务，并核对 `/qq/health` 的真实模式和本次版本；失败会回滚前端及后端。重新提审前仍需人工完成一次真实扫码、回调、刷新和退出验证。

## 广播台后台

管理员可以在同一个网站中进入工作台，完成一次点歌活动所需要的主要操作：

- 开启或调整当前征集期
- 发布面向同学的公告
- 归档已经结束的歌单
- 回看历史征集期
- 复制或下载最终歌单
- 将当前征集期设为测试期，并授权或撤销测试账号

这些能力让点歌活动从“临时收集”变成一个可持续维护的流程，也让每一期歌单都有清晰的开始、结束和记录。

## 项目特点

CHU-小麦点歌台不是一个复杂的音乐平台，也不是面向商业场景的投票系统。它的目标很明确：服务校园广播台的真实工作流。

因此它尽量保持轻量：

- 页面直达投稿，不做多余跳转
- 点赞和榜单围绕当前征集期展开
- 公告、归档、导出都为广播台日常运营服务
- 适配手机和电脑，方便同学访问，也方便工作人员现场管理

## 技术实现

当前前端采用 Vue 3、Pinia 和 Vue Router，使用 Supabase 保存征集期、歌曲投稿、点赞记录和公告内容。用户端与运营端沿用蓝、黄、白品牌配色，结合广播刻度和简洁线框，进入首页即可点歌。

当前项目主要由以下部分组成：

- `apps/user`：用户端，包含点歌、榜单、往期和站内管理入口
- `apps/admin`：独立运营端，使用 Element Plus
- `apps/shared/theme.css`：两端共享的颜色与字体变量
- `public`：保留的旧版静态站，Firebase / GitHub Pages 配置仍指向此目录
- `supabase-schema.sql`：数据库结构和权限策略
- `supabase-admin-workflow.sql`：管理台工作流增量迁移
- `supabase-database-integrity.sql`：关联、并发、限流、旧数据修复与确认歌单快照迁移
- `supabase-test-mode.sql`：测试期、测试账号授权与服务端访问隔离
- `supabase-reset-and-rebuild.sql`：一次清空旧业务数据并完整重建，保留登录账号与管理员名单

本地预览：分别在 `apps/user` 和 `apps/admin` 中执行 `npm run dev`，默认端口为 5173 和 5174。构建分别执行 `npm run build` 与 `npm run build -- --base=/admin/`。ECS 发布流程使用这两个 Vue 应用的构建产物；旧静态站不会自动跟随 Vue 源码更新。

用户端管理入口统一打开独立运营端：本地开发默认使用同一主机的 5174 端口，生产环境默认使用 `/admin/`。如果运营端部署在其他地址，在用户端配置 `VITE_ADMIN_URL` 后重新构建；旧 `/#/admin` 地址也会跳转到统一入口。

点歌草稿保存在当前标签页的 `sessionStorage`，切换页面、改变窗口尺寸和刷新页面均可继续填写，投稿成功或手动清空后移除。榜单支持手动刷新；返回首页或榜单时更新，重新激活页面时按 15 秒间隔去重，并在可见状态下每分钟更新。后台刷新保留列表，失败时标记旧数据并暂停投票，避免征集状态不明时继续操作。

运营端按需加载管理面板、组件样式和柱状图模块。只有完整读取征集期、歌曲、举报和公告后才展示工作台；读取失败提供错误说明和重试入口。所选管理栏目保存在 URL 中，刷新页面后可回到同一栏目。

### 管理台工作流升级

若旧数据不再需要，直接使用下方「清空旧数据并重建」，无需逐份运行迁移。

现有数据库在 Supabase SQL Editor 依次执行 `supabase-admin-workflow.sql`、`supabase-database-integrity.sql`、`supabase-test-mode.sql`；新数据库先执行 `supabase-schema.sql`，再执行上述三个文件。完整序列可重复执行，测试模式迁移必须最后执行，否则重跑完整性迁移会覆盖测试权限入口。已经完成完整性升级的数据库，本次只需执行 `supabase-test-mode.sql`。先导出数据库备份，在维护窗口完成迁移并发布两端前端；不要在业务运行期间单独重跑基础脚本。旧 `supabase-rpc-repair.sql` 已停止覆盖 RPC。此仓库更新不会自动执行远程数据库迁移。

### 清空旧数据并重建

确认旧业务数据可以舍弃时，在 Supabase SQL Editor 新建查询，粘贴并完整执行 `supabase-reset-and-rebuild.sql`，不需要再依次执行其他脚本。它在一个事务中删除本项目的歌曲、投票、举报、征集期、公告、播出歌单、运营/限流/修复日志、安全设置和测试账号授权表，然后安装最新表结构、UUID 关联、管理工作流、RLS 和测试模式。既有 Auth 登录账号（含密码和会话）、`public.admin_users` 管理员名单、Storage 和无关业务表保留，安全设置恢复默认值。脚本不会自动创建征集期或授予任何账号测试权限。

成功后会显示「重建完成」，刷新运营台、新建征集期、重新授权测试账号即可。再次执行此文件也会清空重建之后产生的数据，因此日常升级使用增量迁移。脚本不使用 `DROP SCHEMA` 或 `CASCADE`；未知外部依赖或任一步执行失败都会使整个事务回滚。若报错后 SQL Editor 的连接仍处于失败事务，先执行 `ROLLBACK;` 再处理报错。

`column "period_id" does not exist` 表示完整性迁移尚未补齐关联字段，不能只运行测试模式脚本。保留数据时执行完整迁移序列；舍弃数据时完整执行上面的重建文件。

重建文件由 `node scripts/build-database-reset.mjs` 从五个已测试的迁移生成，修改迁移后须重新生成；本地运行生成命令只更新文件，不连接数据库。重建保留 `qq_accounts` 身份记录，重新安装 QQ 参与权限。`npm run test:db` 包含旧结构重建、全新数据库、账号保留、测试权限、QQ 参与权限，以及删除后失败回滚的测试。

若旧版重建查询出现 `relation "historical_vote_conflicts" does not exist`，请重新复制当前文件的全部内容替换 SQL Editor 中的旧查询，不要只重试旧内容。新版冲突修复在单条 SQL 内完成，不再创建该临时表。重建测试支持 `PG_LOCAL_TEST_URL` 和 `PG_TEST_MODULE_PATH`，可用本地真实 PostgreSQL 验证整份脚本，连接限制与完整性测试相同。

若旧版查询出现 `40P01: deadlock detected`，请换用当前完整重建文件。新版在删除前一次性检查维护锁，表被其他会话占用或已有重建任务时立即停止，并保留原业务数据。执行前关闭用户端、运营台、Supabase Table Editor 和其他正在运行的查询，结束未提交事务；必要时先单独运行 `ROLLBACK;`，再完整执行一次。不要同时打开多个查询运行重建。真实 PostgreSQL 测试包含并发读取、Auth 写入占锁、重复重建任务以及释放锁后成功重建。

### 测试模式

运营台 → 征集期管理 → 测试模式。先在 Supabase 控制台 Authentication → Users 创建邮箱账号、设置密码（关闭自动确认时须完成邮箱验证），再将账号邮箱添加到「测试账号授权」。至少授权一个账号后可以开启当前征集期的测试模式。账号密码通过 Supabase Auth 验证，运营台只保存账号 UUID 和授权记录，不保存明文密码。测试账号不会自动获得管理员权限，管理员参与测试也需单独授权；QQ 账号不作为测试凭证。用户端测试会话使用独立的存储键，不会覆盖运营台会话。

测试期的投稿、投票、取消投票和个人投票查询在数据库校验授权；歌曲读取由 RLS 限制。匿名访客可看到当前测试期提示、登录入口和公开往期，无法查看测试歌曲；归档的测试期也仅对测试账号和运营人员可见。撤销权限后后端立即拒绝后续请求，用户端在刷新、重新聚焦或定时更新时重新校验并清除显示的数据。测试期使用账号 UUID 记录参与身份，改 Cookie 不能绕过账号额度。

开关作用于当前征集期，不自动新建、改名、删除歌曲或重置票数。关闭测试模式后，本期已有内容（包括测试投稿）将公开，界面会明确提示；若希望保留测试数据的访问限制，归档测试期后新建正式征集期。新建征集期默认关闭测试模式。所有模式切换、账号授权和撤销都会留下运营日志。迁移未执行时，正常征集期仍可浏览使用，测试面板会显示升级说明并禁用开关。

- 总览提供举报、截止时间、公告、播出歌单的工作入口，所有栏目显示当前征集期与前台预览。前台另址部署时可配置管理端 `VITE_USER_URL`。
- 新建征集期通过单个事务 RPC 同时归档旧期、创建新期；失败全部回滚。保存前明确说明立即关闭旧期，以及未来开场时间造成的参与空档。
- 歌曲支持修改歌名和歌手、锁定及恢复、状态筛选、分页和操作记录。变更要求填写原因，后端维持同一期歌名与歌手去重，不允许直接修改票数。
- 举报审核保留原因、管理员、时间和历史，可解除歌曲锁定。锁定仅停止投票，前台仍可看到锁定状态；排名参考默认排除，确认播出禁止包含锁定歌曲。
- 公告草稿按管理员保存在本机 `localStorage`，切换栏目或刷新后恢复；支持预览发布、编辑、关闭确认和查看关闭记录。浏览器限制存储时显示草稿无法持久保存的提示。
- 播出歌单按征集期保存到数据库，支持加入候选、确认播出、退回候选、顺序调整、移除及 TXT/复制导出。导出前保存修改并重新核对锁定状态；本机未保存草稿保留，交接须点击保存。版本检查阻止多人编辑时静默覆盖，冲突时重新读取并确认丢弃本机草稿。
- 排名参考提供预览、数量和排序，可显式包含锁定歌曲用于复核；数据 JSON 与所选征集期一致，保留全部明细。它们与最终确认播出歌单分开导出。

验证管理台：在 `apps/admin` 执行 `npm run build -- --base=/admin/` 和 `npm run test:db`。数据库测试使用本地 PGlite，覆盖迁移重复执行、切换失败回滚、歌曲操作留痕、举报审核、歌单版本冲突和权限隔离，不需要线上连接或真实账户。

### 数据库完整性与维护

`supabase-database-integrity.sql` 在一个事务中完成检查、修复和约束安装。检测到多个活跃征集期、孤立关联、错期投票或失效播出条目时，会明确指出表或记录并停止，已执行修改全部回滚；应核实原始数据后重试，不能直接删除冲突数据来绕过检查。

- 歌曲、喜欢、点踩、举报与旧限流记录使用 UUID `period_id` 外键；投票与举报通过复合外键保证和歌曲属于同一期。兼容字段 `playlist_date` 由触发器保持一致。存在关联时禁止删除征集期或歌曲，日常使用归档与锁定。
- 部分唯一索引保证最多一个活跃期。征集期创建、编辑、归档统一通过带权限校验及操作日志的 RPC，管理员不能直接写征集期表。旧无审核原因接口不再对客户端开放。歌名与歌手在用户端、管理台、RPC 和表约束中统一为 1–80 字。
- 同访客同征集期操作和同歌曲计数更新加锁，避免并发突破投稿/点赞额度或同时保留喜欢和点踩。重复歌曲修复先将原始歌曲、票、举报及歌单存入管理员只读的 `database_repair_archive`，再迁移关系；冲突情绪保留最新记录，已审核历史保留，重复待审核项保留最新一项。
- 确认播出由服务端保存歌名、歌手、票数与捕获时间快照；后续改名和调整顺序不改旧快照。需要更新时先退回候选并保存，再重新确认保存。旧歌单仅能补录迁移时的名称，界面会标注来源，不将其冒充为最初确认时的历史。
- 投稿和投票 RPC 的业务失败返回 `error_code` / `error_message`，调用方必须检查，不能仅检查 HTTP 或 Supabase `error`。这样业务回滚仍能提交失败请求的限流计数；两端与保留的静态站已适配。超过限流阈值的请求仍以 RPC 错误返回。取消点踩会删除点踩票，但已提交举报仍等待审核，参与说明已注明。

限流日志只保留必要的 Cookie 摘要、IP、请求类型、期标识与时间，客户端不能读取。由数据库维护任务每日执行 `select public.purge_expired_request_attempts();`，清除超过 7 天的限流日志（不会清除投票、举报或修复档案）。若已启用 Supabase Cron / `pg_cron`，可由数据库所有者一次性配置：

```sql
select cron.schedule('chu-purge-request-attempts', '17 3 * * *',
  'select public.purge_expired_request_attempts();');
```

定时任务需在部署环境配置，仓库迁移不会自动启用扩展或创建外部调度。真实并发验证可在已安装 `pg` 的环境设置 `PG_LOCAL_TEST_URL` 后运行 `node tests/database-integrity.cjs`；仅允许 `localhost` / `127.0.0.1`、名称为 `chu_test_*` 的专用数据库，测试会重建其中 `public` / `auth` schema。可通过 `PG_TEST_MODULE_PATH` 指定 `pg` 模块位置。未设置该环境变量时，`npm run test:db` 只使用内存库。

投稿成功后的链接会定位到对应歌曲并突出显示，推荐卡片也可直接定位到榜单，自动清除搜索并切换到歌曲所在页。歌曲名称与歌手支持点击展开；榜单与往期歌单翻页后会回到当前页列表顶部。往期读取失败后的重试保留已选征集期，失败或读取中不展示零值统计。

用户端可以在浏览器限制存储时继续读取公共歌单和公告，不再创建游客投票身份。投稿和投票必须由 QQ 后端验证 HttpOnly 会话，未登录时不查询个人票态。草稿无法持久保存时会明确提示。首页参与说明介绍征集时间、重复投稿、互斥投票、修改撤回限制与播出安排的公告入口。首次启用须执行保留数据的 `supabase-qq-participation.sql`，并配置后端专用 Supabase Secret key，详见 [QQ 登录接入](docs/QQ_LOGIN.md)。

用户端读取征集期、歌单、个人投票状态和公告时，每次尝试最多等待 10 秒，网络故障和临时服务错误自动重试一次；投稿和投票写入不会自动重试。首页与榜单按断网、超时、验证失败、权限受限、请求过多和接口配置错误分别提示原因与处理建议，可展开失败环节、错误代码、HTTP 状态、数据服务域名和发生时间截图反馈。浏览器无法提供准确原因时会明确说明，不将所有网络失败归为某一原因。网络恢复后自动重连；读取失败仍暂停参与，并保留表单草稿与上次成功读取的数据。运行 `cd apps/user` 后执行 `npm test` 验证读取恢复与诊断分类。

## 项目定位

CHU-小麦点歌台属于校园广播台的线上互动工具。

它关心的不是把功能做得多复杂，而是让一次点歌活动顺畅发生：同学愿意投稿，歌曲可以被看见，热门选择能够浮现，广播台可以高效整理，最后让一份带着校园气息的歌单真正被播放出来。
